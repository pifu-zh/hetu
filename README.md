# 河图 v3 — codex 的长记忆插件

> 河图 v3:前身是"带长记忆的 codex 替代品"探索,重定性为插件后清史
> 重来——不复刻 codex 记忆的采集与归并,只做它没有的检索与透明层。

## 一句话

给 codex 补上它的记忆机制没有的三样东西——**语义检索(向量)、情景找回
(episodic)、透明洞察**——以**单二进制 MCP server** 形态寄生 codex,
零 daemon。

## 为什么有存在必要(对比 codex 内建记忆)

codex 内建记忆(v2 管线)走"自动采集 → LLM 归并 → 子串检索"路线。它的
归并是**有损压缩**:细节在归并中消失,子串搜索找不回语义近邻。河图不做
codex 已做好的事(采集/归并照用它的产物),只做它没做的:

1. **语义检索**:对 codex 自产记忆工件(rollout_summaries、raw_memories.md、
   MEMORY.md——格式已从引擎二进制取证)建向量索引,"归并丢了的细节"用
   语义近邻找回来
2. **情景找回**:episodic 索引,"三周前那个改 build 脚本的下午"级别的
   时间+事件检索
3. **透明洞察**:记忆库全貌可读(什么被记了/什么将过期/什么在膨胀),
   裸 Markdown+SQLite,无魔法

## 形态

- **MCP server**:codex `config.toml` 的 `[mcp_servers.hetu-memory]`
  原生拉起,按需进程,零常驻
- 读取 codex 自产工件为语料,**不重复它的采集与归并**
- 自有增量:向量索引、episodic 索引、TTL/膨胀观测

## 宪法

- **寄生纪律**:每新增一个能力先回答"这是 codex 记忆缺的吗?"——它
  有的(采集/归并/便签/开关)一律不重复实现
- **轻量纪律**:单二进制;无 daemon(codex 按需拉起);v0 无自有 GUI;
  语料与索引全部本地
- **透明纪律**:存储裸 Markdown+SQLite,用户可直接读;检索结果必带
  出处(文件+行号)

## 非目标

- 不做引擎、不做 agent、不做 GUI(v0)
- 不复刻 codex 记忆的任何既有能力
- 不联网:embedding 本地推理或明确降级(裁决见 docs)

## 现状

v0 立项。骨架就绪,第一刀 = 语料接入(codex 记忆工件读取器)+ 检索面。
